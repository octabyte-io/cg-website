Cloudgate keeps everything in one tree: an **Organization** holds **Projects**, a Project holds
**Environments**, and an Environment holds **Services**. Services run on **Servers** or in a
**Cloud account**, both of which belong to the Organization. A **Deployment** is one attempt to
build or run something, a **Plan** is what applying the Project's configuration would change, and an
**Agent** is a member that is an AI tool rather than a person.

- **Organization**: Northwind Labs
  - Members and Agents, with roles and grants
  - Servers (`fra-1`, `nyc-edge`) and Cloud accounts
  - **Project**: `storefront`, with its Project variables and Project config
    - **Environment**: `production`, deploying to `fra-1`

    - **Environment**: `staging`, deploying to `nyc-edge`
      - **Services**: `web`, `pg-main`

## Organization

The Organization is the boundary around everything else. Every Project, Server, Cloud account,
member and setting belongs to exactly one Organization, and people act inside it with a role:
owner, admin or member. On the Hosted instance the Organization is also what has a plan. See
[Organizations](/docs/guide/organizations) and [Members and roles](/docs/guide/members-and-roles).

## Project

A Project groups the Services that ship together, such as a shop's website, API and database. It
holds only Environments, plus its own variables that any Service beneath it can reference by name.
Its **Project config** (a `cloudgate.yaml`, kept in Cloudgate or in your repository) can describe
every Service it runs. See [Projects and Environments](/docs/guide/projects-and-environments).

## Environment

An Environment is a named slice of a Project, such as `production` or `staging`. It owns the
Services and has its own variables. Its **Deploy target** says where new Services are created: a
Server, or a Cloud account and a region. Two Environments of the same Project can run in different
places.

## Service

A Service is one thing that runs. There are three kinds:

- An **Application**, built from a git repository, a Docker image or uploaded files. Its kind can be
  `web`, `worker`, `web-private`, `cron`, `static`, or an AI model.
- A **Database**: PostgreSQL, MySQL, MariaDB, MongoDB, Redis or libSQL.
- A **Compose stack**, from a Docker Compose file.

A **Bucket** for files is a Service too. Services talk to each other through **Wired variables**,
which fill in one Service's variable from another's Output (such as a database's `url`) at each
deploy. See [Applications](/docs/guide/applications), [Databases](/docs/guide/databases) and
[Environment variables](/docs/guide/environment-variables).

## Server or Cloud account

Every Service runs in one place, fixed when it is made:

- A **Server** is a machine Cloudgate reaches over SSH. Its setup run installs Docker, a Swarm of
  one and Traefik, which routes Domains and gets certificates. See [Servers](/docs/guide/servers).
- A **Cloud account** is your AWS account or Google Cloud project. Cloudgate creates the cloud's own
  services there (such as ECS, RDS, Cloud Run or Cloud SQL) with OpenTofu. See
  [Cloud accounts](/docs/guide/cloud-accounts).

On a self-hosted instance, the machine Cloudgate itself runs on, the **platform host**, can also be
a deploy target.

## Deployment

A Deployment is one attempt at one thing, with its own log, status and timings: a build and
release of an Application, a backup run, a cron run, or a run that creates cloud resources. A
Deployment is `pending` while it waits, then `running`, and ends `done`, `error` or `cancelled`.
See [Deployments and rollbacks](/docs/guide/deployments).

## Plan

A Plan is one Environment's list of what applying the Project config would create, change and
destroy. A push to the config's branch, or **Check for changes**, makes one; nothing changes until
someone presses **Apply**. See [Project config and Plans](/docs/guide/project-config).

## Agent

An Agent is a member of the Organization that is not a person: an AI tool connected over MCP. It
has its own role (Reader, Operator or Caller), its own grant to the Projects, Environments and
Services it may reach, and its own keys. It can deploy and read logs, but it never applies a Plan.
See [Agents](/docs/guide/agents) and the [AI agents overview](/ai-agents).

## What the model does not do

<Callout type="limit" title="Fixed by design">
  - Variables are never inherited down the tree. A Service names a Project or Environment value to use it.
  - Nothing moves a Service between Servers or clouds. Make a new one in the new place.
  - Changing an Environment's Deploy target moves nothing that already runs.
  - Every Service belongs to one Environment, and a Server or Cloud account to one Organization.
</Callout>

Every term on this page, and the words Cloudgate avoids, are in the [glossary](/docs/glossary).
