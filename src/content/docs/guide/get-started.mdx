The wizard lives at `/get-started` on the console. You normally reach it from a **Deploy** button on
the [template catalogue](https://cgt.octabyte.io/), which opens it as
`/get-started?template=<app>` with the app chosen. Everything it needs to remember is kept in the
page address, so you can reload, go through payment or confirm your email and land back where you
were. A Template setup in the console that has nowhere to deploy opens the wizard too.

## What you can do

- Deploy any app from the template catalogue without writing any configuration.
- Run it on a Server you already added, a server you buy from Cloudgate (Hosted only), or a server
  you rent elsewhere, such as a VPS.
- Get a working web address at once, over HTTPS on a server with a public address, with passwords
  and keys the app needs made for you.
- See each step as it happens: the server's payment and setup, the launch and the deploy's output.
- Read how to sign in to the app on the last screen.

## How the wizard is laid out

The page is headed **Deploy** and the app's name, with its logo, and "A few steps, and the app runs
on a server of your own". A stepper shows where you are:

| Step | Label | What you do |
|---|---|---|
| 1 | **Choose a server** | Pick or get the Server the app runs on |
| 2 | **Set up** the app | Fill in its values, web address and where it goes, then press **Deploy** |
| 3 | **Launch** the app | Watch it start, then open it |

Before step 1, if you are signed out, the console asks you to sign in or create an account (headed
**Sign in to deploy your app** or **Create your free account to deploy your app**) and brings you
back. See [Sign-in and your account](/docs/guide/sign-in-and-account).

## Step 1: Choose a server

The card asks **Where should** the app **run?** What it offers depends on what your Organization has.

<Screenshot name="get-started-where" alt="The get-started wizard asking where Ghost should run, with Your servers nyc-edge and fra-1, Use nyc-edge, and the option Use my own server" caption="Pick a Server you already have, or connect one of your own." />

### Use a Server you already have

When the Organization has a Server that is ready, the card says "Your server fra-1 is ready for
Ghost" (with your names) and offers **Use fra-1**. With several, **Your servers** lists each with its
address; pick one. **Get a new server instead** shows the two ways below.

A Server counts as ready when it is a deploy Server whose setup succeeded, or a bought Server that
has reached **Ready to use**.

### Get a server from Cloudgate (Hosted only)

**Get a server from Cloudgate**, marked **Recommended**, says "We create the server and set it up
for you. Nothing technical to do." and the lowest price, billed monthly with your plan.

<Steps>
<Step title="Choose the server">
The wizard opens the same choices as the [Buy a Server](/docs/guide/bought-servers) screen: the
location on a world map, the size, the operating system, backups and extra storage, with a summary
beside them.
</Step>
<Step title="Pay">
Buying sends you to Stripe's secure page. If you leave it without paying, the wizard says nothing
was charged.
</Step>
<Step title="Go on while it is made">
After payment, step 2 opens at once with your server's progress in a strip above it, so you can fill
in the details while it is made. See [While a bought server is made](#while-a-bought-server-is-made).
</Step>
</Steps>

On a self-hosted instance, or on the Hosted one while buying is not set up, this card is not shown
at all: **Use my own server** is the only way offered. Opening the buy step's address there anyway
says "Buying a server isn't available here. You can use a server of your own instead." with a
**Use my own server** button. If no size can be bought right now, it says so.

### Use my own server

**Use my own server** is for a server you already rent: "You need its address and SSH access to it."

<Steps>
<Step title="Start a plan, if the Organization has none (Hosted)">
On the Hosted instance an Organization without a plan sees **Start your 30-day free trial** (or
**Choose a plan** if it has had its trial): Starter, up to 3 servers, "$0 today" then the monthly
price. Press **Start free trial** (or **Choose Starter**) and enter your card on Stripe's page. Back in
the wizard, **Thanks. Starting your plan** waits for Stripe to confirm, usually a few seconds, then
moves on by itself. Do not pay again if it takes longer; it keeps checking.
</Step>
<Step title="Describe the server">
Fill in **Your server**:

| Field | What it does | Default |
|---|---|---|
| **Name** | What the console calls the Server | The app's name and "server" |
| **Description** | A note for your team | Optional |
| **Address** | An IP address or a hostname | |
| **SSH port** | The port SSH listens on | `22` |
| **SSH user** | Root, or a user with passwordless sudo | `root` |
| SSH key | The key Cloudgate signs in with | Pick one, or press **Make a key** if the Organization has none |

</Step>
<Step title="Add Cloudgate's key to the server">
Once a key is chosen, the card shows one line to run on the server, signed in as that user. It adds
Cloudgate's public key to `~/.ssh/authorized_keys`:

```bash
mkdir -p ~/.ssh && echo "ssh-ed25519 AAAA... cloudgate" >> ~/.ssh/authorized_keys
```

Copy the exact line from the wizard with its copy button (it holds your real key), run it on the
server, then press **Save and continue**.
</Step>
<Step title="Connect it">
**Connect** the server's name: press **Connect my server**. Cloudgate signs in over SSH ("This takes a
few seconds"), then asks **Run setup on** the server? Confirm, and the card becomes **Setting up** the
server.
</Step>
<Step title="Watch the setup">
The progress names which of the eight setup steps is running and shows the machine's newest line.
**Show what's happening** opens the full output. The setup carries on if you leave; come back to this
page to go on. When it finishes, "fra-1 is ready." and **Continue** opens step 2.
</Step>
</Steps>

The eight setup steps:

1. Installing the basic tools
2. Installing Docker, which runs your apps
3. Getting Docker ready to run apps
4. Creating the network your apps share
5. Making Cloudgate's folders
6. Starting the web gateway that serves your apps
7. Getting the network for AI models ready
8. Making apps start again after a restart

| What you see | What to do |
|---|---|
| **Cloudgate couldn't sign in to your server.** | Check the address, and that the key line was run on the server as the SSH user. Then press **Connect my server** again |
| **Setup stopped:** and a reason | Fix what it names and press **Connect my server** again. Every step checks before it acts, so running it again is safe |
| "Your plan already has all the servers it allows." | An owner or admin adds room on the [Billing page](/docs/guide/billing), or use a Server you already have |

## Step 2: Set up the app

The card is headed **A few details for** the app (or **Ready to deploy** the app when it asks for
nothing), with "Passwords and keys it needs are made for you."

<Screenshot name="get-started-details" alt="Step 2 of the get-started wizard with Ghost's email settings filled in, the Web address with a generated sslip.io host, and Where it goes naming a new Project, Ghost, on fra-1" caption="Only the values the app needs are asked; passwords are generated." />

| Part | What it does |
|---|---|
| The app's values | Only what the template asks for, such as an email sender. A yes-or-no value is a switch. A username field notes that the password is shown on the next screen |
| **Web address** | Each web part gets a host. The wizard fills in a free sslip.io one. Type your own domain instead and the field shows the A record to create, with **Check DNS**; **Generate one for me** puts the free one back. A failed check does not stop the deploy |
| **Where it goes** | One sentence: the Project, the Server and the setup name |
| **More options** | Choose an existing Project instead of a new one, change the **Project name**, and the **Setup name** (each part is named after it) |

Press **Deploy** with the app's name. **Use a different server** goes back to step 1.

Where it goes, by default: a new Project named after the app (with a number if that name is taken)
with a `production` Environment on your Server. If you pick an existing Project, it uses that
Project's Environment on the same Server, or makes a new one.

On a self-hosted instance, the Same-machine warning shows when the app would go on the machine
Cloudgate itself runs on (**This Cloudgate host**, or a Server whose address is that machine): if the
machine is lost, the app and all of Cloudgate's records go with it. It warns and never refuses. The
wizard opens on a Ready Server, so you see it only when the Server you use is that machine.

### While a bought server is made

Above the form, a strip says what your server is doing and which of its stages it is on:
**Payment**, **Creating your server**, **Setting it up**, **Ready to use**. It notes that the app
starts on its own once the server is ready, so you can leave after **Deploy**.

- While it waits for payment: **Finish paying** reopens the payment page; **Cancel this server**
  cancels it and nothing is charged.
- After payment, "Payment made. Confirming it with Stripe" usually takes a few seconds. If your bank
  asked you to approve the payment and you did not, the wizard offers **Finish paying** again.
- **Deploy** turns on once the server is created ("You can deploy once the server is created.").
- If the server could not be created, the card says your payment is being refunded; press **Choose a
  server again**.

## Step 3: Launch the app

**Launching** the app lists its stages: **Preparing**, **Starting**, **Getting its HTTPS
certificate** (on an https address) and **is running**, each with the app's name. "You can leave this
page; it carries on."

- While preparing, it says what it is waiting for, such as the server's setup, and shows that
  setup's progress.
- While starting, it lists each part of the app as **Waiting its turn**, **Downloading and
  starting**, **Started** or **Didn't start**, with the newest line of the deploy's output.
- On an https address it waits for Let's Encrypt, usually under a minute, so your first click does
  not land on a browser warning.

<Callout type="note" title="When the app does not start by itself">
Cloudgate applies the setup for you, as you, once the Server is ready, but only if the
Environment's [Plan](/docs/guide/project-config) holds nothing but what the wizard asked for. If
the Plan holds more, it is left for you to review and **Apply**, and the wizard says why. If the app
did not start, the card says so with the reason and **See what happened**, which opens the
Environment.
</Callout>

## Open your app

When it is running, the card says the app **is running**, with:

- its address and a copy button, and **Open** with the app's name;
- **How to sign in**, when the template says how (below);
- **What next**: **Use your own domain** (shown on an http address) so it is served over https, the
  app's **Variables** tab with all its settings and passwords, **See** the app **in your Project**,
  and **Deploy another app**.

The first visit can take a minute while it finishes starting. If the certificate is still not issued
after the wait, the card says your browser will warn until it is, and, for your own domain, which
address its A record must point at.

## Sign in to your new app

A template may say how a person signs in once the app runs, and the done card follows it under
**How to sign in**:

- **An account made at setup**: "The account the app was set up with": the **Username** (when the
  app asks one) and the **Password**, masked, with **Show** and copy buttons. They are read from the
  stack's own variables, so a member whose role cannot read them sees no password. **Show** widens
  the rows and wraps a long password so it is shown whole. When the sign-in page is not the home
  page, or is on another Domain such as an admin dashboard, **Open** with its path (for example
  **Open /admin**) goes straight there.
- **An account made on the first visit**: where to open the app to make the first account, such as
  `/ghost` for Ghost, with a link to it.

A template that says neither shows no block. Its generated passwords are still on the stack's
**Variables** tab. Template authors write this as `signIn` in `template.yaml`; see
[`signIn` in the CLI reference](/docs/cli/commands#how-a-template-says-to-sign-in-signin).

## HTTPS and your own domain

The address the wizard makes is a free `sslip.io` host. On a server with a public address it is
served over HTTPS with a Let's Encrypt certificate; on a private address, which no certificate
authority can reach, it is plain HTTP. For your own name, type your domain in step 2, or add it to
the Service later, for example `shop.northwind.example`, and point its DNS at the Server. See
[Domains and TLS certificates](/docs/guide/domains).

## What you get

A Project, new and named after the app unless you picked one, with a `production` Environment on
your Server, and the app's Services deployed in it. From here it is an ordinary Project: see
[Projects and Environments](/docs/guide/projects-and-environments).

## What you cannot do

<Callout type="limit" title="Who can use the wizard">
Adding or buying a Server takes a role that may create Servers (owner or admin, or a custom role
that allows it). A member without it sees **Ask your organization's owner or admin**. Deploying onto
a Server that is already ready needs permission to create Services, and to create a Project or an
Environment when the wizard makes one. Starting a plan takes an owner or admin. See
[Members and roles](/docs/guide/members-and-roles).
</Callout>

- Buying a server is offered only on the Hosted instance, and only where buying is set up.
- The wizard deploys onto a Server. To set an app up in a Cloud Environment, use
  [Templates](/docs/guide/templates) in the console instead.
- A link without an app, or with an app the catalogue does not have, shows **That app isn't in the
  catalogue** with **See all apps**.
- An app installed from a template gets no updates from the catalogue afterwards.
