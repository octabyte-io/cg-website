Cloudgate dials every Server with the private half of the key you chose for it, so the public half has
to be in the SSH user's `authorized_keys` on the machine first. One key can serve many Servers. Keys
are managed in one dialog, opened from the [Servers](/docs/guide/servers) screen.

## Where do I manage SSH keys?

Open **Servers** and press **SSH keys** in the header. A Server's **Access** tab opens the same dialog
with **All keys**. When the Organization has no key yet, the **Add a Server** dialog shows **Manage SSH
keys** instead of a picker; after you add a key and press **Done** you are back in Add a Server with
what you typed kept and the new key chosen.

## Add a key

<Steps>
<Step title="Name it">
Enter a **Name**, such as `production-hosts`, and an optional **Description**.
</Step>
<Step title="Generate or paste">
Under **Where the key comes from**:

| Choice | What you enter | What happens |
|---|---|---|
| **Generate one** | A **Type**: **ed25519** (default) or **RSA 4096**. | Cloudgate makes the pair and keeps the private half. |
| **Paste one I have** | **Public key**: one line starting `ssh-ed25519` or `ssh-rsa`. **Private key**: the matching private half. | Both halves are needed. The private key is encrypted at rest. |

Press **Add key**.
</Step>
<Step title="Install the public half">
The new key opens with its public line shown. Press the copy button and add the line to
`~/.ssh/authorized_keys` of the SSH user on each machine that will use the key, for example
`/root/.ssh/authorized_keys` for root.
</Step>
</Steps>

## Use a key for a Server

Choose the key in **Add a Server**, or later on the Server's **Access** tab: press **Change the key**,
pick it under **Which key reaches fra-1**, and press **Save**. Cloudgate does not check the machine when
you save; press **Check now** on the Infrastructure tab to try it.

## Rename or delete a key

Each row shows the key's name, description, when it was added and which Servers use it.

- **Public key** shows and hides the public line with a copy button.
- **Rename** edits the name in place; **Save**, or press Enter. Escape cancels.
- **Delete** asks first and names every Server that uses the key.

<Callout type="warn" title="Deleting a key strands its Servers">
A delete is not refused while Servers use the key. Those Servers are left with no key: nothing can be
deployed to them, read from them or opened in a shell until you choose another key on each one's
**Access** tab.
</Callout>

## What you cannot do

<Callout type="limit" title="Owners and admins">
Adding, renaming and deleting SSH keys needs the owner or admin role, or a custom role that allows it.
</Callout>

- See or download a private key after it is added.
- Replace a key's halves in place. To rotate, add a new key, install it, choose it, then delete the old one.
- Use a password instead of a key for a Server.
