An Agent has its own role, its own grant to the Projects, Environments and Services it may reach,
and its own **agent keys**. It acts only through the MCP endpoint, the console's address plus
`/mcp`, and every call it makes, allowed or refused, is a row in the [audit log](/docs/guide/audit-log).

## What you can do

- Create Agents with the Reader, Operator or Caller role.
- Grant each one only the Projects, Environments and Services it needs.
- Issue, rotate and revoke its agent keys.
- Suspend an Agent at once, and resume it later.
- Copy ready-made configuration for Claude Code, VS Code, Cursor and Codex CLI.

## Agent roles

| Role | What it can do |
|---|---|
| **Reader** (default) | Reads what it is granted: Services, Environments, Deployments, Deployment logs and Domains. Changes nothing. |
| **Operator** | Everything a Reader can, and deploys, starts, stops and cancels Deployments of what it is granted. Cannot change settings, variables or access. |
| **Caller** | Calls the AI models it is granted through the Gateway, and nothing else. Gets no tools over MCP. |

## Create an Agent

<Steps>
<Step title="Open Agents">
Open **Settings** > **Agents** and press **Create an Agent**.
<Screenshot name="settings-agents" alt="Settings, Agents for Northwind Labs, with a deploy-bot Agent holding the Operator role, its grant to storefront and its keys" caption="Each Agent shows its role, what it can reach, its keys and when a client last connected." />
</Step>
<Step title="Name it and pick a role">
Give it a **Name** that says what it is for, such as `deploy-bot` or `staging reader`; it is how
the audit log names it. Pick a **Role**: Reader is selected by default.
</Step>
<Step title="Grant access">
Under **Access**, tick what it may reach, for example the `storefront` Project's `staging`
Environment. Access starts empty, and granting a Service grants its Project and Environment too.
You can save it with nothing granted and grant it later.
</Step>
<Step title="Choose when its first key expires">
Under **First key expires**, choose **In 30 days**, **In 90 days** (the default) or **In a year**.
Press **Create Agent**.
</Step>
<Step title="Copy the key">
The first key is shown once. Copy it into your MCP client's secret storage now.
</Step>
</Steps>

## Connect an MCP client

On the Agent's row, press **Connect**. The panel holds the configuration for **Claude Code**
(`.mcp.json`), **VS Code** (`.vscode/mcp.json`), **Cursor** (`~/.cursor/mcp.json`), **Codex CLI**
(`~/.codex/config.toml`) and any other client. Each sends the key as
`Authorization: Bearer <agent key>` to your console's address plus `/mcp`.

<Screenshot name="agent-connect" alt="The Connect panel for deploy-bot, with tabs for Claude Code, VS Code, Cursor, Codex CLI and other clients, showing a configuration snippet" caption="Pick your client and paste its snippet; the key stays in your client's secret storage." />

Step-by-step client setup is in [Connect an MCP client](/docs/mcp/connect).

## Rotate, suspend or delete an Agent

- **Add key** issues another key with its own expiry. To rotate, add a key, switch the client to
  it, then **Revoke** the old one. An expired key shows **Remove**.
- **Suspend** refuses its next call through the MCP endpoint, and every one after, until you press
  **Resume**.
- **Change role** and **Manage access** change what it can do and reach.
- **Delete** removes the Agent, its access and all its keys. Its audit trail stays.

<Callout type="warn" title="Deleting an Agent cannot be undone">
Every client using its keys stops working at once. To stop it for now, use **Suspend** instead.
</Callout>

## What you cannot do

<Callout type="limit" title="Guard rails">
- Every agent key expires: there is no "never".
- An Agent can never be an owner or an admin.
- An Agent asks for a Plan but never applies or dismisses one, and reads health but never
  configures checks or thresholds.
- Rate limits: 120 reads and 10 writes a minute per Agent, shared across its keys.
- An agent key works only at the MCP endpoint and the Gateway, never on the REST API or for
  sign-in.
- Cloudgate does not give an Agent access to your git repository; you do that outside Cloudgate.
</Callout>
