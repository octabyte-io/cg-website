The examples use an AI model named `support-assistant` in the `production` Environment of
`storefront`, on the Server `fra-1`, called by a `web` Application through a caller Agent named
`support-chat`.

## What can you do with an AI model?

- Serve one model with **Ollama**, **vLLM** or **llama.cpp**, on the CPU or on reserved GPUs.
- Call it with any OpenAI client through the Gateway: chat, completions, embeddings, streaming.
- Give each calling Service its own caller Agent and key, and suspend one without the others.
- See **Token spend** per Agent and model, over 7, 30 or 90 days or since it was created.
- Point Cloudgate's own AI features at your model, in **Settings** > **AI**.

## How do I add an AI model?

Press **Add an AI model** on the Environment's **Services** tab, choose the Server, runtime and model,
then create and deploy it:

<Steps>
<Step title="Open the Environment">
Open the Environment and its **Services** tab, then press **Add an AI model**.
</Step>
<Step title="Fill in the dialog">
Fill in the fields in the table below. The Server picker shows each Server's GPUs and how many are
free right now.
<Screenshot name="ai-model-create" alt="The Add an AI model dialog with Name, Description, Server fra-1 with no GPUs set up, Inference runtime set to vLLM, Model, Hugging Face token and GPUs" caption="The runtime is fixed once the AI model is created; the model and GPUs can change later." />
</Step>
<Step title="Create it">
Press **Create AI model**. It opens on its **Model** tab, not yet deployed.
</Step>
<Step title="Deploy it">
Press **Deploy**. The first Deployment pulls (Ollama) or loads (vLLM, llama.cpp) the model; wait
until the AI model reads as ready before calling it.
<Screenshot name="ai-model-model-tab" alt="The Model tab of the llm AI model, with its Ollama runtime and model llama3.1:8b, the Connect a client card, and the Token spend card" caption="Connect a client holds the endpoint once the instance has an address; the Token spend chart counts calls by day." />
</Step>
</Steps>

| Field | What it does | Notes |
|---|---|---|
| **Name** | What it is called in Cloudgate, such as `support-assistant`. | |
| **Description** | Optional: what it is for. | |
| **Server** | Where it runs. Each entry reads, for example, `fra-1 · 2 GPUs, 1 free`, or "no GPUs set up". | Servers not ready are turned off. On a self-hosted install it opens on the first Ready Server; choosing this Cloudgate host, or a Server on Cloudgate's own machine, warns that Cloudgate itself runs there. |
| **Inference runtime** | **Ollama**, **vLLM** or **llama.cpp**. | Fixed once created. |
| **Model** | The one model it serves, in that runtime's naming (below). | |
| **Hugging Face token** | For gated weights. Given to the model as `HF_TOKEN`, never shown again. | vLLM and llama.cpp only. |
| **GPUs** | Whole cards per running copy. | `0` runs it on the CPU. |

| Runtime | Model naming | Example |
|---|---|---|
| Ollama | Ollama's own names | `llama3.2:3b` |
| vLLM | a Hugging Face repo id | `Qwen/Qwen2.5-0.5B-Instruct` |
| llama.cpp | a Hugging Face GGUF repo id, with a quant after the colon if you want one | `ggml-org/gemma-3-1b-it-GGUF:Q4_K_M` |

One AI model serves one model. A chat front end that also embeds documents needs two: one chat
model and one embedding model.

<Callout type="limit" title="Who can add one">
**Add an AI model** is shown only to people with the `service: create` permission (owners and
admins). An AI model runs on a Server, or on a Self-hosted install on this Cloudgate host.
</Callout>

## Which tabs does an AI model have?

An AI model is an Application, so it has an Application's tabs with **Model** second: **Overview**,
**Model**, **Deployments**, **Logs**, **Shell**, **Variables**, **Health**, **Traces**,
**Advanced**, **Rollbacks**, **Schedules** and **Volume backups**. It has no **Domains**,
**Requests**, **Previews** or **Patches**: it is reached only through the Gateway, and nothing
about it is built from source. Change its GPUs on **Advanced**, in the **Resources** card. See
[Applications](/docs/guide/applications) for the shared tabs.

## What is on the Model tab?

- **Model**: the **Inference runtime**, the **Image** it runs (marked **Off the pin** when you chose
  another tag), and **GPUs reserved**. Change the **Model** or the **Image tag** here; leave the tag
  empty to run the one the platform was tested with. Neither reaches the running AI model until the
  next Deployment.
- **Hugging Face token** (vLLM and llama.cpp): whether one is set, a field to set or replace it, and
  **Remove token**. The running model keeps the token it started with until the next Deployment.
- **Connect a client**: the **Endpoint**, an OpenAI SDK for JavaScript snippet, **Create a caller
  Agent**, and **Agents that can call it**.
- **Token spend**: tokens and calls through the Gateway.

## How do I call it through the Gateway?

Every call enters through the **Gateway**, an OpenAI-compatible proxy inside Cloudgate. The
**Connect a client** card shows the **Endpoint**:

```text
https://<console domain>/ai/<AI model id>/v1
```

If the card says there is no endpoint yet, the instance has no console domain or server IP: set
one in **Settings** > **Instance**.

<Steps>
<Step title="Create a caller Agent">
Press **Create a caller Agent**. It opens the Agents dialog on the **Caller** role with a grant on
this AI model and its Environment and Project. Name it after the Service that will call, such as
`support-chat`, and copy its key: it is shown once. The button is shown only to people who may add
members to the Organization.
</Step>
<Step title="Set the calling Service's variables">
On the calling Service's **Variables** tab, set the two names the OpenAI SDKs read by themselves,
and the model name every call must give:

```bash
OPENAI_BASE_URL=https://<console domain>/ai/<AI model id>/v1
OPENAI_API_KEY=<the caller Agent's key>
AI_MODEL=llama3.2:3b
```
</Step>
<Step title="Deploy the caller">
Deploy the calling Service. It can run anywhere: on the same Server, another one, another Project,
or outside Cloudgate.
</Step>
</Steps>

```python
import os
from openai import OpenAI

client = OpenAI()  # reads OPENAI_BASE_URL and OPENAI_API_KEY
reply = client.chat.completions.create(
    model=os.environ["AI_MODEL"],
    messages=[{"role": "user", "content": "Summarise our refund policy."}],
)
print(reply.choices[0].message.content)
```

**Agents that can call it** lists every Caller Agent granted this AI model, with **Suspended** on
a suspended one; you need to be able to read the Organization's members to see it. To let one Agent
call a second AI model, grant it that AI model in **Settings** > **Agents**. See
[Agents](/docs/guide/agents).

### What does the Gateway forward and refuse?

The Gateway forwards four calls: `POST /v1/chat/completions`, `POST /v1/completions`,
`POST /v1/embeddings` and `GET /v1/models`. Streams are passed on as the runtime produces them, and
a call has no deadline. A body may be up to 16 MiB. Refusals come in the OpenAI error shape, so a
client shows the sentence:

| Status | Message | Why |
|---|---|---|
| 401 | `Key refused` | Unknown, revoked or expired key, a personal key, or a suspended Agent. |
| 404 | `AI model not found or not permitted` | No such AI model, or the Agent is not a Caller granted it. |
| 404 | `The gateway forwards only POST /v1/chat/completions, ...` | Any other path, including the runtime's own API. |
| 400 | `This AI model serves '<model>'; set "model" to it` | The body names another model. It is never rewritten. |
| 400 | `The request body is not valid JSON` | The body could not be read. |
| 413 | `The request body is larger than the gateway takes (16 MiB)` | The body is too large. |
| 503 | `AI model is not running` | Never deployed, or stopped. |
| 502 | `AI model did not answer` | The Gateway could not reach the runtime. |

<Callout type="tip" title="One caller Agent per calling Service">
Token spend is broken down by the Agent that called. A key shared across your stack makes all of
its spend one line, and suspending it cuts everyone off.
</Callout>

## How do I see token spend?

The **Token spend** section on the **Model** tab shows tokens over **7 days**, **30 days**,
**90 days** or **All**, by UTC day, as a chart and a table per **Agent** and **Model served**, with
**Tokens**, **Of which estimated** and calls per outcome (`ok`, `runtime-error`, `client-aborted`,
`refused`). Tokens are **reported** by the runtime or **estimated** when it gives none, such as a
cut stream. A removed Agent keeps its row, marked **Removed**. With no calls yet it reads "No
calls" for the window.

Spend belongs to the AI model, not the caller: it adds up to the AI model's Environment and
Project, which show **Token spend, 30 days**, and the Environment's **Services** tab has a
**Spend** column. Per-call entries are kept 90 days; daily totals for as long as the AI model
exists.

## How do I change the model?

Save a new **Model** on the **Model** tab, then deploy. The Gateway starts holding calls to the new
name at once, but the runtime serves it only after the Deployment finishes. Save, deploy, then
update the callers' `AI_MODEL`.

## What is Settings, AI for?

**Settings** > **AI** lists the **AI providers** Cloudgate itself calls: an OpenAI-compatible
endpoint, such as a hosted provider, Ollama, or one of your own AI models. A provider powers two
features elsewhere in the console:

- **Draft one with AI** on an Environment's **Services** tab: describe what you need and get up to
  three complete Compose stacks to choose from. The one you pick becomes an ordinary Compose stack,
  not deployed until you deploy it.
- **Explain this log** on a Deployment's log: what is on screen is sent to the provider, which
  answers with a summary, the errors, the likely cause and what to change.

<Screenshot name="settings-ai" alt="The AI providers list in Settings, AI, with no provider yet, and the card What a provider is used for" caption="Add a provider to draft Compose stacks and explain build logs." />

Press **Add a provider** and fill in:

| Field | What it does | Notes |
|---|---|---|
| **Name** | What the provider is called in Cloudgate. | |
| **API URL** | The base URL you would give an OpenAI client, such as `https://api.openai.com/v1`. | For one of your AI models, its **Endpoint**. |
| **API key** | The provider's key; for your AI model, a caller Agent's key. | Stored encrypted, never shown again. Empty when editing keeps the saved one. |
| **Model** | Exactly as the provider spells it. **List models** asks the endpoint with the key you typed and fills it in. | |
| **Available to use** | Off keeps the provider and stops it being offered. | On by default. |

**Test connection** sends one token through the model. With a key typed in it tests those values;
with the key left empty it tests the provider as saved. The list shows **Name**, **Model**,
**Endpoint** and **In use**. Deleting a provider deletes its key; Compose stacks already drafted
with it are not affected.

<Callout type="limit" title="Who can manage providers">
Adding, editing, testing and deleting providers, and **List models**, are for owners and admins.
Any member can use the features a provider powers. An API URL that resolves to a private address
works only for the instance's own Organization: on an install with several Organizations, the
others must use a public address.
</Callout>

## What you cannot do

- Reach an AI model except through the Gateway: it has no Domain, published port, previews or
  patches.
- Change its inference runtime after it is created.
- Let an Agent create or delete an AI model: only a person can. Agents may deploy, start, stop
  and read it.
- Rate-limit a caller at the Gateway: there is no per-Agent limit. Suspend the Agent to stop one.
- Keep calls open across a Cloudgate restart: the Gateway runs inside the backend, so callers
  should retry.
- Back up a model's weights volume: the weights are downloaded again instead.

<Callout type="limit" title="The last hop is plain HTTP">
Calls enter at the console's address and go back out to the AI model's Server over plain HTTP,
guarded by a per-model secret. Keep Servers that run AI models on a network you trust. Without a
console domain, a stream that goes quiet for four minutes is cut.
</Callout>
