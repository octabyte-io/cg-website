A preview is not a Service and not an Environment. It is a copy of one Application, built from a
branch, that shares the parent's storage and Environment and answers on its own host under a
wildcard Domain.

There are two kinds:

- **Pull-request preview**: opened by a pull request against the tracked branch, one per pull
  request, removed when it closes. GitHub-sourced Applications only.
- **Requested preview**: asked for by a person or an [Agent](/docs/guide/agents) for any branch,
  and torn down when it expires.

## What you can do

- Build a preview for every pull request, up to a limit you set.
- Allow requested previews, for example so an AI agent can show you its fix running.
- Give previews their own variables and build arguments.
- Extend, redeploy or expire a requested preview; redeploy or tear down a pull-request preview.

## Set up previews

<Steps>
<Step title="Point a wildcard at the Server">
Create a DNS record for a wildcard host, for example `*.preview.northwind.example`, pointing at
the Application's Server. It must resolve before previews can be reached.
</Step>
<Step title="Open Preview settings">
Open the Application, then **Previews** > **Preview settings**.
<Screenshot name="application-previews" alt="The Previews tab of the web Application with the preview settings and a list of open previews" caption="Settings at the top, open previews below." />
</Step>
<Step title="Fill in the settings">
- **Wildcard host**: the host you pointed above. You can also issue the wildcard certificate
  through DNS-01 with Let's Encrypt.
- **Container port**: the port the app listens on.
- **Preview variables**: replace the Application's variables in previews. Left empty, previews use
  production's.
- **Preview build arguments**: build arguments for preview builds.
- **Build a preview for every pull request** and **Most previews at once**.
- **Allow requested previews** and **Most requested previews at once** (3 by default, counted apart
  from pull-request previews).
</Step>
<Step title="Save">
Open a pull request against the tracked branch. Its preview appears in the list with its address
once built.
</Step>
</Steps>

<Callout type="warn" title="Previews use production's data">
A preview shares the Application's storage and, unless you set **Preview variables**, its
variables too. A preview that writes to the database writes to production's database. Point
previews at a separate database before you turn them on for code that writes data.
</Callout>

## Ask for a requested preview

A requested preview is created through the API or MCP, not from a console button:

- An Agent calls `create_preview` with the Application and branch, and optionally a lifetime in
  minutes. See [MCP tools](/docs/mcp/tools).
- A script calls `POST /applications/{applicationId}/preview-deployments`. See the
  [API reference](/docs/api).

Whoever may deploy the Application can ask, but only while **Allow requested previews** is on.
Each call makes a new preview, even for the same branch.

## Extend, redeploy or expire a requested preview

The **Requested previews** list shows each preview's branch, who asked for it, when it expires and
its latest build.

- **Extend** sets a new expiry a number of minutes from now. It replaces the window; it does not
  add to it.
- **Redeploy** builds the branch again. It never moves the expiry.
- **Expire now** tears it down at once.

A requested preview lives 60 minutes by default. The longest a request may ask for is the
instance's **Requested preview lifetime**, 24 hours unless the operator changed it (self-hosted,
Settings > Instance).

## What you cannot do

<Callout type="limit" title="Which Applications can have previews">
Only Applications built from git. A Docker image source, uploaded files, a `worker`, a
`web-private` and an AI model have no previews.
</Callout>

- Pull-request previews need a GitHub source.
- Create a requested preview from the console; use the API or MCP.
- Extend a preview that has already expired; ask for a new one.
- Turning **Allow requested previews** off refuses new ones; previews already running stay until
  they expire.
- Turning on requested previews needs permission to update the Application, which no Agent role
  has.
