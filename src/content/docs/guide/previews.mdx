A preview is not a Service and not an Environment. It is a copy of one Application, built from a
branch, that runs against the parent's volumes and Environment and answers on its own host under a
wildcard Domain. Each preview build is a Deployment, listed on the Application's **Deployments**
tab.

There are two kinds:

- **Pull-request preview**: opened by a pull request against the tracked branch, one per pull
  request, torn down when it closes. GitHub-sourced Applications only.
- **Requested preview**: asked for by a person or an [Agent](/docs/guide/agents) for any branch,
  and torn down when it expires.

## What can you do with previews?

- Build a preview for every pull request, up to a limit you set.
- Allow requested previews, for example so an AI agent can show you its fix running.
- Give previews their own variables and build arguments.
- Redeploy or tear down a pull-request preview; extend, redeploy or expire a requested one.

## Set up previews

<Steps>
<Step title="Point a wildcard at the Server">
Create a DNS record for a wildcard host, for example `*.preview.northwind.example`, pointing at the
Application's Server. Nothing in Cloudgate creates it, and it must resolve before previews can be
reached.
</Step>
<Step title="Open the Previews tab">
Open the Application and its **Previews** tab. **Preview settings** sits at the top, then
**Pull-request previews** and **Requested previews**.
<Screenshot name="application-previews" alt="The Previews tab of the web Application with Preview settings, a requested preview of feature/gift-cards and pull request 142 Wishlist on product pages under the wildcard preview.northwind.example" caption="Settings at the top, open previews below." />
</Step>
<Step title="Fill in Preview settings">
| Field | What it does | Default |
|---|---|---|
| **Build a preview for every pull request** | Pull requests against the tracked branch get a preview. | Off. |
| **Wildcard host** | Each preview gets its own host under it. | Required to turn previews on. |
| **Issue the wildcard certificate through DNS-01 (Let's Encrypt)** | Gets one wildcard certificate for every preview host. | Off. Needs a wildcard and a DNS-01 setup on the Server (its Settings tab, or the platform host's Traefik settings). |
| **Most previews at once** | Pull-request previews only. A pull request opened when this many run is refused, not queued. Zero turns them off. | 3. |
| **Container port** | Where the preview's container listens. | 3000. |
| **Preview variables** | One `KEY=value` per line; replaces the Application's own variables for previews. | Empty: previews use production's. |
| **Preview build arguments** | The same, for `--build-arg` on the preview build. | Empty: production's. |
| **Allow requested previews** | Lets a person or Agent who may deploy ask for a preview of a branch. | Off. |
| **Most requested previews at once** | Counted apart from pull-request previews; an expired one counts until its teardown finishes. At least 1. | 3. |

Press **Save changes**. None of it reaches a preview already running until it is redeployed.
</Step>
<Step title="Open a pull request">
Open a pull request against the tracked branch. Its preview appears under **Pull-request
previews** with its host once built.
</Step>
</Steps>

<Callout type="warn" title="Previews use production's data">
A preview mounts the Application's own volumes and, unless you set **Preview variables**, uses its
variables too. A preview that writes to the database writes to production's database. Point
previews at a separate database before you turn them on for code that writes data.
</Callout>

## Manage pull-request previews

The **Pull-request previews** card lists **Pull request**, **Branch**, **Host**, **Status** and
**Opened** for each one.

- **Redeploy** builds the head of its branch again.
- **Tear down** removes the preview now.

The card warns when **Every pull request is refused** (**Most previews at once** is 0) or
**Every slot is taken**. With none open it says "No pull request is open", or "Previews are off for
this Application".

## Ask for a requested preview

A requested preview is created through the API or MCP, not from a console button:

- An Agent calls `create_preview` with the Application and branch, and optionally a lifetime in
  minutes. See [MCP tools](/docs/mcp/tools).
- A script calls `POST /applications/{applicationId}/preview-deployments`. See the
  [API reference](/docs/api).

Whoever may deploy the Application can ask, but only while **Allow requested previews** is on. Each
call makes a new preview, even for the same branch.

## Extend, redeploy or expire a requested preview

The **Requested previews** card lists **Branch**, **Host**, **Status**, **Requested by**,
**Expires**, **Latest build** and **Created**.

- **Extend** opens **Extend the preview of** the branch. Enter **Minutes from now**: the new window
  replaces what was left of the old one. The instance's maximum is shown in the hint.
- **Redeploy** builds the branch again. Its expiry stays where it is.
- **Expire now** tears it down; its copy goes within the minute.

A requested preview lives 60 minutes by default. The longest a request may ask for is the
instance's **Requested preview lifetime**, 24 hours unless the operator changed it (self-hosted,
Settings > Instance). With requested previews off, **Extend** and **Redeploy** are greyed out;
**Expire now** stays.

## What you cannot do

<Callout type="limit" title="Which Applications can have previews">
Only Applications built from git. A Docker image source and uploaded files have no Previews tab,
and a `worker`, a `web-private`, a Cron service and an AI model take no previews.
</Callout>

- Pull-request previews need a GitHub source.
- Create a requested preview from the console; use the API or MCP.
- Extend a preview that has already expired; ask for a new one.
- Queue a preview when the limit is reached: it is refused.
- Turning **Allow requested previews** off refuses new ones; previews already running stay until
  they expire.
- Changing Preview settings needs the update action on Services, which no Agent role has.
