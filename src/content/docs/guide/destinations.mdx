Destinations live at **Settings** > **Destinations** (`/settings/destinations`) and belong to the
whole Organization: every Project's backups can use them. Cloudgate reaches a bucket with rclone,
so anything S3-compatible works.

## What you can do

- Add an S3-compatible bucket as a Destination.
- Test that Cloudgate can reach it, before saving or at any time later.
- Edit its endpoint, bucket and keys.
- Remove it once nothing uses it.

A Destination is then picked in a database's **Backups** tab (scheduled dumps) and in a volume
backup. See [Backups](/docs/guide/backups) for schedules and restores.

## The Destinations screen

<Screenshot name="settings-destinations" alt="The Destinations card listing the bucket northwind-backups with its endpoint and region eu-central-1" caption="Destinations are shared by every Project in the Organization." />

| Column | What it shows |
|---|---|
| **Name** | The name you gave it. |
| **Bucket** | The bucket's name. |
| **Endpoint** | The API endpoint, with the region under it, or **No region**. |
| Actions | **Edit** and **Remove**. |

The table says which buckets are configured, not whether anything has been written to them. To see
what is actually in a bucket, use the dumps list on a database's **Backups** tab or the volume
restore flow. With none yet, the screen says **No destinations yet** with **Add a destination**.

## Add a destination

<Steps>
<Step title="Open the dialog">
Open **Settings** > **Destinations** and press **Add a destination**.
</Step>
<Step title="Describe the bucket">

| Field | What it does | Notes |
|---|---|---|
| **Name** | What this bucket is called in Cloudgate, such as `northwind-backups`. | Required. Only shown in Cloudgate. |
| **Endpoint** | The API endpoint, with its scheme, such as `https://s3.eu-west-1.amazonaws.com`. | Required. MinIO, R2 and others have their own. |
| **Region** | The bucket's region, such as `eu-west-1`. | Optional. Leave it empty if your provider has no regions. |
| **Bucket** | The bucket's name, such as `cloudgate-backups`. | Required. |
| **Provider** | rclone's own provider name when the bucket needs one: AWS, Minio, Wasabi, Cloudflare. | Optional. Left empty, rclone works it out. |
| **Access key** | The key id. | Required. |
| **Secret access key** | The secret. | Required when adding. Stored encrypted and never shown again. |
| **Test from** | The Server the test runs from. | Hosted only. Servers not ready yet are greyed out. |

<Screenshot name="destinations-add" alt="The Add a destination dialog filled in for a Cloudflare R2 bucket named Offsite backups, with its endpoint, bucket, provider and keys" caption="Test the connection before you save it." />
</Step>
<Step title="Test the connection">
Press **Test connection**. "Cloudgate listed ... with the key you typed." means it can reach the
bucket. A failure shows rclone's message, with your keys hidden.
</Step>
<Step title="Save it">
Press **Add a destination** to save it.
</Step>
</Steps>

<Callout type="tip" title="Keep backups off the machine">
A Destination on another provider or region survives losing the Server the data is on. That is the
only kind of backup that survives losing that machine.
</Callout>

## How does Test connection work?

- Adding: it needs the **Secret access key** filled in, since nothing is saved yet; it probes
  the bucket with what is typed.
- Editing, with the secret typed in: it probes the values in the dialog.
- Editing, with the secret left empty: it probes the Destination as it is saved. "Cloudgate
  reached this destination as it is saved" means the stored one works; anything changed in the
  dialog was not part of that test.
- On the Hosted instance: choose a Server under **Test from** first. The test runs from that
  Server, because this Cloudgate does not run checks from its own host. With no Servers, the field
  says to add one first.

## Edit a destination

Press **Edit** on its row. The dialog, "Edit ...", holds the saved values except the secret. Leave
**Secret access key** empty to keep the saved one, or type a new one to replace it. Press **Save
changes**.

## Remove a destination

Press **Remove** on its row. "Remove ...?" explains that nothing in the bucket is deleted: only
Cloudgate's credentials for it go. Press **Remove destination**, or **Keep it**.

<Callout type="limit" title="Not while backups use it">
A Destination still used by a database backup schedule or a volume backup cannot be removed. The
refusal names each one and the Service it is on: point them at another Destination, or delete them,
first.
</Callout>

## Who can manage destinations?

Owners and admins, or a custom role that allows it.

<Callout type="limit" title="Owners and admins">
Adding, editing, testing and removing Destinations takes an owner or an admin, or a custom role that
allows it. Members cannot. Without the right, the buttons are greyed out with the reason.
</Callout>

## What you cannot do

<Callout type="limit" title="Limits">
- Only S3-compatible storage; no SFTP, FTP or local folders.
- The secret access key is never shown again.
- Removing a Destination never deletes what is in the bucket, and is refused while a backup uses it.
- Destinations are per Organization, not per Project.
</Callout>
