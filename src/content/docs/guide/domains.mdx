On a Server, each Domain is a Traefik route to one Service, with a certificate from Let's Encrypt,
one you upload, a resolver of your own, or none. In a Cloud account, a Domain sits on the cloud's
own load balancer or CDN with the cloud's own certificate. Either way you create the DNS record;
Cloudgate shows which one and checks it.

## What can you do with Domains?

- Add your own hostname, such as `shop.northwind.example`, to an Application, a Compose stack or a
  bucket.
- Get a free `sslip.io` hostname that needs no DNS at all.
- Serve over HTTPS with Let's Encrypt, a stored certificate, or a certificate resolver you set up.
- Route only a path, such as `/api`, and strip it before the request reaches the container.
- Require sign-in in front of a host with [forward auth](/docs/guide/forward-auth).
- See whether the certificate has been issued, and whether Traefik is serving the route.

## What is on the Domains tab?

Open an Application and its **Domains** tab. The **Domains** card lists each host the Application
answers on.

<Screenshot name="application-domains" alt="The Domains tab of the web Application listing shop.northwind.example and www.northwind.example, each on port 3000 with HTTPS and a Let's Encrypt certificate" caption="Each row is one host, with its path, port, HTTPS and certificate." />

| Column | What it shows |
|---|---|
| **Host** | The host as a link, then its path (with **stripped** when the path is stripped), the container port, and **HTTPS** or **HTTP**. "Not being routed" marks a host whose router Traefik refused. |
| **Certificate** | **Let's Encrypt**, **Stored certificate** (with its name), **Custom** (with the resolver), or **Not managed here** for HTTP. With Let's Encrypt it says whether the certificate is issued. |
| **Sign-in** | A switch that puts this host behind the [forward-auth](/docs/guide/forward-auth) sign-in proxy. |
| | **Edit** and **Remove**. |

A strip above the table says changes reach Traefik within a second, with no Deployment. The side
card **Internal address** says how other Services reach this one without a Domain: on a Server, at
its **Host** (its internal name) on `cloudgate-network`, on whatever port it listens on, with no
certificate and no trip through Traefik.

With no Domain yet, the card says "No domain points here yet" with **Add a domain**; the dialog can
generate a working host if you do not own one.

## Add a custom domain on a Server

<Steps>
<Step title="Open the dialog">
On the **Domains** tab, press **Add a domain**.
<Screenshot name="application-add-domain-dialog" alt="The Add a domain dialog on the web Application with shop.northwind.example typed as the Host, the A record to create pointing at 203.0.113.10, a DNS check that says it does not point here yet, and Serve over HTTPS on with Let's Encrypt" caption="The record to create, the DNS check, then HTTPS and the certificate." />
</Step>
<Step title="Enter the host, port and path">
| Field | What it does | Default |
|---|---|---|
| **Host** | The hostname visitors type, such as `shop.northwind.example`. No scheme, no path. | Empty. |
| **Container port** | The port the Application listens on inside its container. | `3000`. |
| **Path** | Route this path and everything under it: `/api` takes `/api` and `/api/…`, not `/apix`. Ending it in `/` takes only what is under it: `/v2/` takes `/v2/…` but not `/v2`. | `/`, the whole host. |
| **Strip the path before proxying** | The Application receives `/` instead of the path above. | Off. Needs a path other than `/`. |
</Step>
<Step title="Create the DNS record and check it">
Under the host, the dialog shows **The record to create at your DNS provider**: an `A` record whose
**Name** is the part in front of your zone (`shop` for `shop.northwind.example`, `@` for the bare
domain) and whose **Value** is the Server's public address. Create it, then press **Check DNS**:

- "shop.northwind.example points here." The record is right.
- "… does not point here yet." It resolves elsewhere or not at all; DNS changes can take a while to
  spread, so correct the record and check again.
- "… is behind Cloudflare" (or Bunny, Fastly, Arvancloud): Cloudgate cannot see past the proxy, so
  make sure the CDN's own origin is the Server's address.
</Step>
<Step title="Turn on HTTPS and choose the certificate">
**Serve over HTTPS** starts off. Turn it on, and Traefik redirects HTTP to HTTPS and terminates
TLS. Then pick the **Certificate**:

| Certificate | What it does |
|---|---|
| **Let's Encrypt** | Issued automatically once DNS points at the Server. |
| **Stored certificate** | Served from a certificate stored in Cloudgate that covers this host; a wildcard counts. A host none covers is refused. Certificates added under **Settings → Certificates** are for the platform host; a remote Server can use one only if a certificate was stored for that Server. |
| **Custom resolver** | A certificate resolver you configured on the Server's Traefik, named in **Traefik resolver** (letters, numbers, `_` and `-`). |
| **None** | Not allowed with HTTPS on. For a host behind a CDN or proxy that terminates TLS, turn HTTPS off instead. |

A stored certificate that covers the host is always served instead of Let's Encrypt or a resolver.
</Step>
<Step title="Save">
Press **Add domain**. If the Application is running it answers on the host at once; if it is
stopped, it answers after its next Deployment or Start.
</Step>
</Steps>

Let's Encrypt issues the certificate on the first request after the record resolves.

## Use a free sslip.io address

In the **Add a domain** dialog, press **Generate one for me** beside **Host**. Cloudgate writes a
hostname such as `web.203.0.113.10.sslip.io`. sslip.io answers from the name itself, so there is no
record to create and it works at once.

When the Server's address is public, **Generate one for me** also turns on **Serve over HTTPS**
with **Let's Encrypt**. On a private address it leaves HTTPS off. Anything you change after
pressing it is kept. It needs the Server's public address recorded; for an Application on the
Cloudgate host of a self-hosted instance, record the host's address under Settings > Instance.

## Check that the HTTPS certificate is issued

Until Let's Encrypt answers, Traefik serves its own self-signed certificate, and a browser warns
about it. Cloudgate reads the certificate the host really serves, and the **Certificate** column
says which of three it is:

- **Let's Encrypt · issuing, usually under a minute**: the self-signed one is still served. The tab
  reads it again every few seconds.
- **Let's Encrypt · valid until** a date: the real certificate is served.
- **Let's Encrypt · not issued yet**: check that the A record points at the Server's address and
  that port 80 is reachable. Each attempt is in the Server's Traefik log, linked from the cell.

The Overview's **Domain** card says the same beside the address. A stored or custom certificate
warns only when what the host serves would not be trusted. The
[get-started wizard](/docs/guide/get-started) waits on the same read before it shows **Open**. A
script can read it at `GET /domains/:id/served-certificate`; see the [API](/docs/api).

## What if Traefik refuses a route?

When Traefik refuses the Application's routing configuration, a banner on the Domains tab says
"Traefik refused this Application's routing configuration." and, per host, "shop.northwind.example
is not being routed." with what Traefik reported and when. The host's row is marked too. Traefik
drops a router whose middleware it cannot build, so a bad redirect or basic-auth user is the usual
cause; [Application settings](/docs/guide/application-settings#routing-port-published-ports-redirects-and-basic-auth)
marks the candidates. If Cloudgate could not ask Traefik at all, the banner says so: nothing then
says whether the hosts are served.

## Edit or remove a Domain

**Edit** opens the same dialog as **Edit shop.northwind.example**; **Save changes** reaches Traefik
as soon as it is saved.

**Remove** asks "Remove shop.northwind.example?": nothing deployed is deleted, only this route. The
Application stops answering on it straight away. If the same host has other paths, the dialog says
which requests still answer. Press **Remove domain**, or **Keep it**. Removing a Domain also deletes
the [Uptime checks](/docs/guide/monitoring) on it, and never touches your DNS.

## Upload your own certificate

For a host Let's Encrypt cannot issue for, open **Settings → Certificates** > **Add a certificate**.
Give it a name, paste the PEM certificate chain and the private key. The private key is never shown
again. Then choose **Stored certificate** on the Domain. See
[Certificates](/docs/guide/certificates) for the details.

<Callout type="limit" title="Who can manage Domains and certificates">
Members can add, edit and remove Domains on the Services they are granted. A certificate added in
the console is for the platform host, and adding one needs an owner or an admin of the instance's
own Organization, so on the Hosted instance customers cannot add one: use Let's Encrypt instead.
</Callout>

## Redirect a URL or ask for a password

Redirects and basic authentication are set on the Application's **Advanced** tab, **Routing**
section, and protect every Domain it answers on. See
[Add a redirect](/docs/guide/application-settings#add-a-redirect) and
[basic authentication](/docs/guide/application-settings#ask-for-a-password-with-basic-authentication).

## Put a CDN in front of a Service

Cloudgate has no CDN integration: you set the CDN up at your provider. **Check DNS** recognises
Cloudflare, Bunny CDN, Fastly and Arvancloud and stops at the proxy. If the CDN terminates TLS
itself, leave **Serve over HTTPS** off on the Domain, so Traefik does not ask Let's Encrypt for a
certificate it cannot get.

## Add a domain in a Cloud account

A Service in a Cloud account is always served over HTTPS with the cloud's own certificate (ACM on
AWS, Google-managed on Google Cloud). Open the Service's **Domains** tab and press **Add a domain**.

<Steps>
<Step title="Enter the host">
Type the **Host**, such as `shop.northwind.example`, and an optional **Path**, then press **Add
domain**.
</Step>
<Step title="Create the records it shows">
The row shows the validation record for the certificate and the record that points the host at
the cloud, each with copy buttons and whether it is seen in DNS yet. On AWS a subdomain gets a
`CNAME`; a bare name needs an `ALIAS`, `ANAME` or flattened `CNAME`, never an `A` record. On Google
Cloud it is an `A` record to the network's fixed address.
</Step>
<Step title="Wait for Live">
The Domain moves through **Waiting for DNS**, **Checking** and **Live**, or **Failed** with the
reason. Each change runs as its own short Deployment.
</Step>
</Steps>

Until a Domain is added, a Cloud Run Service answers at its `run.app` address and an AWS static
site at its CloudFront name, both shown as **Generated** rows. A static site on Google Cloud has no
address of its own, and a Compose stack on a Stack VM has no generated host. Removing a cloud
Domain lists the records to delete at your DNS provider.

## What you cannot do

<Callout type="limit" title="Limits">
- Cloudgate never creates or deletes DNS records, on a Server or in a cloud.
- A worker, a private web service, a Cron service and an AI model take no Domain; the button is
  greyed out and says why.
- A host is unique per Server on a Server, and per Organization in a cloud.
- An AWS static site takes one Domain, because CloudFront serves one certificate.
- Compose stacks cannot be put behind forward auth.
</Callout>
